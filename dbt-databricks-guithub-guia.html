Por que o pre-hook resolve

O mesmo SQL funcionou no SQL Editor e falhou no dbt. A diferença estava na sessão.

✓ SQL Editor do Databricks

Sessão abre no catálogo dev

sessão: dev.dbt_lmiranda
CREATE OR REPLACE TABLE dev.dbt_lmiranda.teste …

Funciona. Prova que o catálogo e o schema estão bons.

✕ dbt sem ajuste

Sessão abre no hive_metastore

sessão: hive_metastore
create or replace table `dev`.`dbt_lmiranda`.`my_first_dbt_model` …

Mesmo com o catálogo no nome da tabela, o Databricks recusa, porque a sessão aponta para o catálogo desativado.

→ Correção no dbt_project.yml

Trocar o catálogo da sessão antes de cada modelo

+pre-hook: "USE CATALOG dev" roda antes do create table. A sessão passa a apontar para dev e o comando é aceito.

O +database: dev coloca o catálogo no nome das tabelas; o +pre-hook acerta a sessão. Os dois juntos fazem o dbt run passar.

O final do dbt_project.yml

models:
  my_new_project:
    +database: dev
    +pre-hook: "USE CATALOG dev"

seeds:
  my_new_project:
    +database: dev
    +pre-hook: "USE CATALOG dev"
    banvic:
      +schema: erp_banvic
      +enabled: false

No projeto original o bloco models: vem comentado com #. Tire o #, mantenha o recuo de 2 e 4 espaços e use o mesmo nome que aparece em name: no topo do arquivo.

O que não foi necessário

Tentativas feitas durante o diagnóstico que não resolveram o problema:

trocar o catálogo para workspace mudar o default catalog do Databricks reiniciar o Studio dbt restart studio

Os erros deste caminho

401dbt debug falha com “Unauthorized”
Credential was not sent or was of an unsupported type for this API … HTTP 401 Unauthorized

Causa: o Token ID (64 caracteres) foi colado no lugar do token.

Correção: gere um novo token no Databricks e cole o valor que começa com dapi.

hivedbt run falha com UC_HIVE_METASTORE_DISABLED_EXCEPTION
Failed to create schema 'dbt_lmiranda' in database 'hive_metastore' … [UC_HIVE_METASTORE_DISABLED_EXCEPTION] The operation attempted to use Hive Metastore, which is disabled…

Causa: a sessão do dbt abre no hive_metastore, que vem desativado no Free Edition.

Correção: +database: dev e +pre-hook: "USE CATALOG dev" no dbt_project.yml (passo 4.2).

hiveO schema passou, mas a tabela falhou

Sinal de que só o +database foi aplicado. Falta o +pre-hook. Ative Debug logs no painel do erro: se o comando mostrar `dev`.`schema`.`tabela` e mesmo assim falhar, o problema é a sessão.

seedsO erro voltou ao ativar os seeds do BanVic

Os seeds precisam do mesmo ajuste. Confira se o bloco seeds: também tem +database: dev e +pre-hook: "USE CATALOG dev" antes de mudar +enabled para true.

forkO pull request foi para o repositório da Indicium

Em forks, o GitHub sugere o repositório original como destino. Na tela do PR, troque base repository para seu-usuario/banvic-dbt antes de criar.

uiO campo Catalog parecia preenchido, mas estava vazio

Texto em cinza dentro do campo é só uma dica. Clique, apague e digite dev: o texto precisa ficar branco antes de salvar.

schemaDe onde veio o schema dbt_lmiranda?

O dbt gera o schema a partir do seu nome: inicial do primeiro nome + último sobrenome. Não é erro; pode manter ou trocar nas credenciais.

cmd“dbt restart studio” falhou

Não é um comando do dbt. Reiniciar o Studio é uma opção da interface, em Status no rodapé. Neste caminho, não foi necessário.
